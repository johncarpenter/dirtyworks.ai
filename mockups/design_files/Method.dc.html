Method / 01 — Before production

Good AI operations begin before the login.

Product choice matters. So do account ownership, source quality, access, training, integrations, support, tests, cost controls, incidents, and exit. We make those decisions visible before production and keep them current afterward.

02 / Lifecycle work order

Map it. Deploy it. Operate it.

Map
Step 01
Inputs

Current products, accounts, people, information, integrations, spend, and recent failure events.

Work performed

Inventory, interviews, permission spot checks, cost pull, problem framing.

Customer decision

Confirm scope of the map and who can be interviewed.

Output / gate

Current-state record.

Gate / Scope agreed
Design
Step 02
Inputs

Current-state record, business priorities, existing systems.

Work performed

Smallest viable product mix, overlap and prerequisite analysis, owner and control design, commercial route.

Customer decision

Choose the mix, or choose to consolidate instead.

Output / gate

Scope, route, and owner map.

Gate / Design review
Approve
Step 03
Inputs

Proposed scope, data boundary, cost estimate, responsibilities.

Work performed

Write purpose, permitted use, exclusions, tests, and stop conditions.

Customer decision

Named approver signs the operating scope.

Output / gate

Approved use record.

Stop gate
Deploy
Step 04
Inputs

Approved scope, identity environment, approved sources.

Work performed

Customer-owned accounts, roles and settings, approved connections, tests, documentation, training.

Customer decision

Approve access grants and the pilot cohort.

Output / gate

Runbook and training record.

Gate / Test pass
Stabilize
Step 05
Inputs

Deployed configuration, bounded cohort, support channel.

Work performed

Resolve access and quality problems, confirm cost signals, tune guidance.

Customer decision

Accept, extend the pilot, or stop.

Output / gate

Acceptance record.

Release gate
Operate
Step 06 / monthly
Inputs

Live service, tickets, telemetry, vendor notices, spend.

Work performed

Users, support, monitoring, controls, incidents, vendor change, spend, renewals, one improvement.

Customer decision

Approve changes with material risk or cost.

Output / gate

Monthly operating record.

Loop → map / design

03 / Valid review outcomes

Selling another tool is not the required outcome.

Deploy Consolidate Repair first Use a simpler tool Keep it human Stop

A useful review removes uncertainty. Sometimes that supports deployment. Sometimes it exposes duplicate tools, weak sources, missing ownership, unacceptable risk, or work that does not need AI.
